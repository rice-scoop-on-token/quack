# PC 웹 STT 검증 기록

2026-11-13에 이분 탐색 설명을 Windows 녹음기와 Chrome에서 녹음하고, OpenAI의 `gpt-transcribe`로 전사했다. Chrome에서는 Windows 입력 테스트를 통과한 Razer Seiren X를 선택한 뒤 재녹음했다.

| 녹음과 요청 조건 | 응답 시간 | 결과 |
| --- | ---: | --- |
| Windows 녹음기 M4A, 첫 요청 | 1.25초 | HTTP 400 `unsupported_value`. 거절된 필드는 확인되지 않았다. |
| 같은 M4A, 파일명과 `audio/mp4` 명시 | 2.21초 | 전사 성공. ‘정렬된 배열’, ‘절반’, ‘O(log n)’의 의미가 보존됐다. |
| 첫 Chrome WebM, 마이크 재선택 전 | 1.94초 | HTTP 200, 빈 전사문. 로컬 재생에서도 목소리가 들리지 않았다. |
| 재녹음한 Chrome WebM, 힌트 없음 | 1.59초 | ‘이번 탐색’, ‘비로그 n’으로 전사됐다. ‘정렬된 배열’과 ‘절반’은 보존됐다. |
| 같은 Chrome WebM, `이분 탐색`·`O(log n)` 힌트 | 1.26초 | ‘이분 탐색’은 바로잡혔고 ‘비로그 n’은 그대로였다. |

Chrome WebM과 Windows M4A 모두 파일 전사가 가능했다. 힌트 비교는 같은 녹음의 조건별 1회 관측이다. 응답 시간은 요청 시작부터 응답 수신까지의 관측값이다.

## Quack 연결 기준

- 사용자가 녹음을 끝내면 브라우저 파일을 서버로 보낸다. 서버는 파일명과 MIME 타입을 유지해 OpenAI 전사에 전달한다.
- 앱에서는 녹음 종료 후 전사문을 기존 설명 분석에 바로 넘긴다. 녹음 중 입력 레벨을 보여주고, 음성이 거의 들어오지 않으면 녹음 상태를 안내한다. 브라우저 검증 페이지의 레벨은 신호 크기를 보여주며 발화 유무를 확정하는 지표로 쓰지 않는다.
- 빈 전사문과 외부 API 실패는 서로 다른 결과로 처리한다. 빈 전사문은 학습 분석에 넘기지 않는다.
- 전사 요청에 한국어 언어 힌트(`languages[]=ko`)를 사용한다. 호출자가 제공한 용어 힌트는 `keywords[]`로 보낸다. 앱 연동 시 주제에서 예상되는 용어만 제공하고, 실제 발화에 없는 용어가 전사문에 생기는지도 확인한다.
- 분석에는 `input_mode: "voice"`를 전달한다. ‘비로그 n’처럼 의미를 확인할 수 없는 전사 구절은 오류나 누락으로 집계하지 않고, 그 구절에 의존하는 판정은 `unverified`로 둔다. 실제로 명확하게 설명된 부분은 기존 기준으로 분석한다. 이 처리는 모델에 주는 분석 지침이며, 전사 오인식을 확정적으로 검출하는 장치의 정확도를 검증한 결과는 아직 없다.
- 수식·숫자·부정 표현이 포함된 새 녹음에서 전사문과 사람이 작성한 원문을 각각 분석해, 이해 판정이나 꼬리 질문이 얼마나 달라지는지 비교한다. 새 음성 평가 결과로 자동 재전사의 필요성을 판단한다.
- BE는 `/speech/transcribe`에서 인증·업로드 제한·사용량 처리와 응답의 `duration_ms` 출처를 정한다. OpenAI가 보고하는 오디오 사용량 초는 녹음 길이와 다를 수 있다. 이번 WebM은 로컬에서 8.82초, API 사용량에서는 9초였다.
