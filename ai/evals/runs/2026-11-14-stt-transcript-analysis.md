# 음성 전사 오인식이 설명 분석에 미친 영향

2026-11-14 한국 시간 기준 [STT Draft #26](https://github.com/rice-scoop-on-token/quack/pull/26)의 `e2ad37a` 분석 코드로 비교했다. 학습 목표는 “이분 탐색에서 범위를 절반씩 줄이는 과정이 시간 복잡도와 어떻게 연결되는지 설명한다”다.

기준 입력에는 사용자가 제공한 발화를 그대로 썼다. 비교 입력은 마지막의 “빅 오 로그 엔”만 기존 Chrome WebM 시험에서 관측된 “비로그 n”으로 치환했다. 문장 전체는 평가용 재현이며 이번 비교에서 음성을 다시 전사하지 않았다. 두 요청 모두 `input_mode: "voice"`를 사용했다. 참고 자료와 이전 대화는 비웠고, 러버덕으로 설정했다.

## 비교 결과

| 항목 | 기준 발화 | 오인식 재현 |
| --- | --- | --- |
| 답 상태 | `correct` | `not_applicable` |
| 이해 상태 | `insufficient` | `unverified` |
| 독립 수행 | `unverified` | `unverified` |
| 오류 | 0개 | 0개 |
| 누락 | 반감 횟수와 로그의 관계 설명 | 반감 횟수와 입력 크기의 관계 설명 |
| 대화 행동 | `ask` | `ask` |
| 응답 시간 | 10.532초 | 11.013초 |

기준 발화에서는 모델이 `O(log n)`을 정확히 인식했다. 탐색 범위의 절반 축소도 확인했지만, 원소가 하나 남을 때까지 몇 번 줄여야 하는지의 근거를 더 요청했다. 수식 표현은 정확했고, 왜 로그가 나오는지 설명하는 학습 목표는 추가 확인이 필요하다는 평가다.

오인식 재현에서는 모델이 `비로그 n`을 개념 오류나 누락으로 기록하지 않았고, 의도한 수식을 대신 채워 넣지 않았다. 정렬된 배열에서 가운데 값과 비교하고 범위를 줄인다는 내용은 인정했다. 이해는 `unverified`로 보류했고, 두 입력에서 별도로 빠진 반감 횟수의 근거를 물었다. 다만 답 상태는 `unverified`가 아니라 `not_applicable`이었다. 이 차이가 모호한 수식 표현의 처리와 개념 설명이라는 과제 유형 중 무엇에서 비롯됐는지는 이 비교만으로 확인하기 어렵다.

**기준 발화의 질문**

> 원소가 n개일 때, 범위가 한 개 정도 남을 때까지 줄이는 횟수가 왜 log n이 되는지 연결해 줄래?

**오인식 재현의 발화와 질문**

> 정렬된 배열에서 가운데 값을 비교하며 범위를 절반씩 줄인다는 건 따라왔어.
>
> 원소가 n개일 때, 범위를 절반씩 줄여 탐색을 끝내기까지의 비교 횟수는 n과 어떤 관계가 있어?

## 판단과 범위

이번 관측에서는 전사 불명확성을 오답으로 돌리지 않고 명확한 부분을 인정한다는 기준을 충족했다. 질문도 재녹음이나 전사문 수정을 요청하는 대신 학습 목표에 남은 관계를 물었다. 두 입력에 각각 한 번 호출했으므로, 오인식이 있는 다른 수식·숫자·부정 표현에서도 같은 처리를 하는지와 반복 안정성은 미확인이다.
