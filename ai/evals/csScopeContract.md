# 공부 시작 전 학습 목표 범위 확인 API 계약 초안

## 무엇을 했나

`POST /sessions/start` 한 요청에서 서버가 학습 목표의 범위를 확인하고, 허용된 경우에만 세션을 만드는 방식을 제안한다. 지원 과목은 자료구조·알고리즘·컴퓨터구조다. 구체적인 경로와 응답 형식은 FE·BE 검토안이다.

## 왜 이렇게 했나

현재 `api.startSession`은 mock 세션을 만든 뒤 타이머로 이동한다. 시연 연결은 첫 설명을 보낼 때 원격에 폴더와 별도의 세션을 만든다. 새 흐름은 서버가 반환한 실제 세션 ID를 첫 설명부터 종료까지 재사용해야 범위 확인과 저장의 대상이 일치한다.

## 정해 둔 것 (팀 확인 필요)

### 요청·응답 제안

기존 익명 로그인 사용자의 인증으로 요청한다. `folder_id`는 서버에 존재하는 사용자 소유 폴더 UUID이고 `goal`은 앞뒤 공백을 제거한 비어 있지 않은 목표다. 최대 140자는 현재 FE 입력 제한에 맞춘 제안이다. `request_id`는 공부 시작을 한 번 시도할 때 만드는 UUID다.

```json
{
  "folder_id": "11111111-1111-4111-8111-111111111111",
  "goal": "직접 사상 캐시에서 히트를 판단하는 방법을 설명한다.",
  "request_id": "22222222-2222-4222-8222-222222222222"
}
```

| 정상 응답 HTTP 200 | 응답 필드 | 앱에서 할 일 |
| --- | --- | --- |
| `in_scope` | `{ status, session }` | 기존 shared `Session` 형식의 원격 세션을 받아 타이머를 시작한다. |
| `out_of_scope` | `{ status, message }` | 지원 과목을 안내하고 준비 화면의 목표 입력을 유지한다. |
| `needs_clarification` | `{ status, message }` | 목표를 구체화하는 질문을 보여주고 준비 화면의 목표 입력을 유지한다. |

범위 밖 안내 문구안은 “지금은 자료구조, 알고리즘, 컴퓨터구조를 지원해요. 이 세 과목 중 하나로 학습 목표를 바꿔 주세요.”다. 구체화 문구안은 “세 과목 중 어떤 개념을 공부하고 싶나요?”다. 안내 문구는 서버에서 정한 문장을 사용한다. 두 안내 결과에는 세션이 없다.

기술 오류에는 기존 `{ error: { code, message } }`를 사용한다. 빈 입력·형식 오류는 `VALIDATION_FAILED`, 소유 폴더가 없으면 `NOT_FOUND`다. 모델의 시간 초과·잘못된 출력 등 판정 실패는 `AI_FAILED`로 구분하고 세션을 만들지 않는다. 서버 설정 실패·권한·사용량 오류는 기존 공통 코드로 연결한다. 범위 확인에 차감할 사용량 종류와 한도는 BE가 결정한다.

같은 사용자가 같은 `request_id`와 같은 정규화 입력으로 다시 요청하면, 이미 만들어진 세션을 재사용한다. 같은 ID에 다른 입력이 들어오면 `INVALID_STATE`를 반환하는 안이다. 목표나 폴더를 바꾸면 새 ID를 쓴다. 동시에 같은 ID가 들어와도 세션은 하나만 저장되도록 BE가 DB 제약 또는 트랜잭션으로 보장해야 한다.

### 담당별 검토 요청

- **FE:** 공부 준비 화면에서 원격 `startSession` 결과에 따라 이동하거나 목표를 유지한다. 확인 중 연속 제출을 막고, 응답을 받기 전에 연결이 끊기면 같은 `request_id`로 다시 요청한다. 타이머 화면·설명 제출·종료에서 같은 원격 세션 ID를 사용하고 현재 mock 세션 조회와 원격 폴더의 연결을 어떻게 옮길지 정한다.
- **BE-B:** 인증과 폴더 소유권을 확인한 뒤 `classifyGoalScope`를 호출한다. `in_scope`에서만 세션을 저장한다. 범위 안내와 기술 오류의 응답을 구분하고 shared 요청·응답 스키마를 FE와 맞춘다.
- **BE-A:** 현재 `authenticated`의 `sessions` 직접 INSERT 권한으로는 시작 API를 우회할 수 있다. 기존 그림자 세션 경로의 전환 순서와 직접 INSERT 제한, 재시도 중복 방지, 사용량 정책을 검토한다. 전환 이후에는 앱 계정이 판정을 건너뛰어 세션을 만드는 경로도 확인한다.
- **AI:** 목표 판정만 맡는 클라이언트를 제공한다. 성공의 `status`와 호출 실패를 구분한다. BE는 기존 서버 모델 설정을 전달하고, FE 문구나 세션 저장은 이 모듈 외부에서 처리한다.

## 확인한 것

[범위 확인 사례 9개](csScopeCases.md)에서 기대 판정을 정했고, [실제 모델 평가](csScopePrompt.md)에서 모두 일치했다. 계약 연동에서는 허용 때만 타이머가 열리는지, 안내·오류 뒤 입력이 남는지, 재시도 시 세션 ID가 중복되지 않는지 확인한다.

새 모듈의 오프라인 시험 9개와 기존 설명 분석 회귀 시험 22개가 통과했다. 새 모듈에 들어간 지시와 JSON 스키마가 9개 모델 사례를 평가한 문서와 일치함을 확인했다. 세 가지 판정, 잘못된 입력·응답, 호출 오류와 타임아웃을 가짜 응답으로 시험했다. `pnpm typecheck`와 서버 `deno check`도 통과했다.

## 아직 못 한 것

FE·BE 검토를 거쳐 API 경로·공통 스키마·중복 방지 방식을 확정하고, 기존 mock·그림자 세션 연결을 전환한다. 앱에서 공부 시작부터 설명·종료까지 실제 요청으로 검증하는 작업은 연동 뒤 진행한다.
