# 공부 시작 전 학습 목표 범위 확인 API 계약

## 무엇을 했나

`POST /sessions/start` 한 요청에서 서버가 학습 목표의 범위를 확인하고, 허용된 경우에만 세션을 만드는 흐름이다. 지원 과목은 자료구조·알고리즘·컴퓨터구조다. 요청·응답 스키마는 [PR #25](https://github.com/rice-scoop-on-token/quack/pull/25)에서 `main`에 병합됐다.

## 왜 이렇게 했나

현재 `api.startSession`은 mock 세션을 만든 뒤 타이머로 이동한다. 시연 연결은 첫 설명을 보낼 때 원격에 폴더와 별도의 세션을 만든다. 새 흐름은 서버가 반환한 실제 세션 ID를 첫 설명부터 종료까지 재사용해야 범위 확인과 저장의 대상이 일치한다.

## 요청과 응답

기존 익명 로그인 사용자의 인증으로 요청한다. `folder_id`는 서버에 존재하는 사용자 소유 폴더 UUID이고 `goal`은 앞뒤 공백을 제거한 비어 있지 않은 목표다. 최대 길이는 140자다. `request_id`는 공부 시작을 한 번 시도할 때 만드는 UUID다.

```json
{
  "folder_id": "11111111-1111-4111-8111-111111111111",
  "goal": "직접 사상 캐시에서 히트를 판단하는 방법을 설명한다.",
  "request_id": "22222222-2222-4222-8222-222222222222"
}
```

| 정상 응답 HTTP 200 | 응답 필드 | 앱에서 할 일 |
| --- | --- | --- |
| `in_scope` | `{ status, session }` | 기존 shared `Session` 형식의 원격 세션을 받아 타이머를 시작한다. |
| `out_of_scope` | `{ status }` | 지원 과목을 안내하고 준비 화면의 목표 입력을 유지한다. |
| `needs_clarification` | `{ status }` | 목표 구체화 안내를 보여주고 준비 화면의 목표 입력을 유지한다. |

FE는 두 안내 응답의 `status`에 맞춰 준비 화면에서 고정 문구를 표시한다. 범위 밖이면 지원 과목 세 가지를 안내하고, 구체화가 필요하면 목표를 좁혀 달라고 안내한다.

기술 오류에는 기존 `{ error: { code, message } }`를 사용한다. 빈 입력·형식 오류는 `400 VALIDATION_FAILED`, 소유 폴더가 없으면 `404 NOT_FOUND`다. 모델의 시간 초과·잘못된 출력 등 판정 실패는 `502 AI_FAILED`로 처리하며 세션을 만들지 않는다. 서버 설정 실패·권한·사용량 오류는 기존 공통 코드로 연결한다.

응답을 받지 못했거나 `AI_FAILED`가 발생한 뒤 같은 입력으로 재시도할 때는 같은 `request_id`를 쓴다. 같은 사용자·ID·정규화 입력으로 이미 만든 세션이 있으면 재사용한다. 같은 ID로 다른 입력을 보내면 `409 INVALID_STATE`를 반환하며, 이 오류 뒤 재시도에는 새 ID를 쓴다. 목표나 폴더를 바꾸거나 새로 공부를 시작할 때도 새 ID를 만든다.

## 연동 담당

- **FE**는 확인 중 연속 제출을 막고, `in_scope`에서 받은 원격 세션 ID를 타이머·설명 제출·종료에서 함께 사용한다. 시연용 서버 폴더 준비와 기존 그림자 세션 경로 전환 시점은 BE-B와 맞춘다.
- **BE-B**는 `request_id` 저장 칸과 `(user_id, request_id)` 유일 제약을 추가하고, 앱 계정의 세션 직접 생성 권한을 회수하는 마이그레이션을 맡는다. 이후 `/sessions/start` 라우트와 저장소를 연결한다. 인증과 폴더 소유권을 확인한 뒤 `classifyGoalScope`를 호출하고, `in_scope`일 때만 세션을 저장한다. [담당과 진행 순서](https://github.com/rice-scoop-on-token/quack/pull/25#issuecomment-6919266431)
- **AI**는 목표 판정 클라이언트를 제공한다. 클라이언트는 성공 결과의 `status`와 호출 실패를 구분한다.

## 확인한 것

[범위 확인 사례 9개](csScopeCases.md)에서 기대 판정을 정했고, [실제 모델 평가](csScopePrompt.md)에서 모두 일치했다. 계약 연동에서는 허용 때만 타이머가 열리는지, 안내·오류 뒤 입력이 남는지, 재시도 시 세션 ID가 중복되지 않는지 확인한다.

새 모듈의 오프라인 시험 9개와 기존 설명 분석 회귀 시험 22개가 통과했다. 새 모듈에 들어간 지시와 JSON 스키마가 9개 모델 사례를 평가한 문서와 일치함을 확인했다. 세 가지 판정, 잘못된 입력·응답, 호출 오류와 타임아웃을 가짜 응답으로 시험했다. `pnpm typecheck`와 서버 `deno check`도 통과했다.

## 아직 못 한 것

BE-B의 마이그레이션과 라우트 연결, 시연용 서버 폴더 준비, FE의 기존 mock·그림자 세션 전환이 남아 있다. 범위 판정에 적용할 AI 사용량 종류는 팀에서 정한다. 앱에서 공부 시작부터 설명·종료까지 실제 요청으로 검증하는 작업은 연동 뒤 진행한다.
