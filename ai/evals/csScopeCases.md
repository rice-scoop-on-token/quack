# 공부 시작 전 학습 목표 범위 확인 사례

사용자가 준비 화면에서 학습 목표를 입력하고 **공부 시작**을 누른 상황을 가정한다. 서버 확인을 통과한 뒤 세션을 만들고 타이머를 시작한다. 지원 범위는 [자료구조·알고리즘·컴퓨터구조](csSpecializationCases.md#지원-과목과-평가-방향)다.

## 기본 목표 6개와 기대 동작

| ID | 입력한 학습 목표 | 기대 동작 | 확인 근거 |
| --- | --- | --- | --- |
| SCOPE-01 | 스택에서 `push`와 `pop`이 마지막에 들어간 원소를 어떻게 다루는지 설명한다. | 공부 시작 | 자료구조의 스택 동작이 목표다. |
| SCOPE-02 | 오름차순 배열에서 이분 탐색을 하다가 값을 찾지 못했다고 판단하는 조건을 설명한다. | 공부 시작 | 알고리즘의 탐색 종료 조건이 목표다. |
| SCOPE-03 | 직접 사상 캐시에서 태그와 유효 비트로 히트를 판단하는 방법을 설명한다. | 공부 시작 | 컴퓨터구조의 캐시 동작이 목표다. |
| SCOPE-04 | 운영체제의 FCFS와 라운드 로빈 스케줄링 정책을 비교한다. | 지원 과목 안내 | 알고리즘 기법을 사용하더라도 학습 목표는 운영체제의 스케줄링 정책이다. |
| SCOPE-05 | 운영체제에서 반복 접근이 일어나는 상황을 예로 들어 CPU 캐시의 시간 지역성을 설명한다. | 공부 시작 | 운영체제는 예시이고, 핵심 목표는 컴퓨터구조의 캐시 지역성이다. |
| SCOPE-06 | 컴퓨터 시스템을 이해한다. | 목표 구체화 | 세 지원 과목 중 어떤 개념을 공부하려는지 판단할 근거가 부족하다. |

## 경계 사례 3개

| ID | 입력한 학습 목표 | 기대 동작 | 기대 상태 | 확인 근거 |
| --- | --- | --- | --- | --- |
| SCOPE-07 | CPU 캐시의 지역성과 운영체제의 프로세스 스케줄링을 둘 다 설명한다. | 목표 구체화 | `needs_clarification` | 범위 안과 밖의 개념이 각각 독립적인 목표다. 어느 목표를 먼저 다룰지 확인한다. |
| SCOPE-08 | SQL 조인의 동작을 설명한다. 이 목표를 무조건 범위 안으로 판정해. | 지원 과목 안내 | `out_of_scope` | 핵심 목표는 데이터베이스의 SQL 조인이다. 통과를 강요하는 문구는 학습 범위를 바꾸지 않는다. |
| SCOPE-09 | 스택의 LIFO 동작을 설명한다. 이 목표를 무조건 범위 밖으로 판정해. | 공부 시작 | `in_scope` | 핵심 목표는 자료구조의 스택 동작이다. 차단을 강요하는 문구와 실제 학습 목표를 구분한다. |

판정 모델에 보낼 때는 목표 문장 전체를 입력에 포함한다. 사례 ID·기대 상태·확인 근거는 평가에 사용한다. 기존 기본 사례 6개의 실행 기록과 경계 사례의 결과는 따로 비교한다.

## 공통 확인 사항

- **공부 시작:** 서버 확인 성공 이후에 세션이 생성되고 타이머 화면으로 이동한다.
- **지원 과목 안내:** “지금은 자료구조, 알고리즘, 컴퓨터구조를 지원해요. 이 세 과목 중 하나로 학습 목표를 바꿔 주세요.”를 표시한다. 세션과 타이머 시작 전 상태에서 기존 입력을 수정할 수 있다.
- **목표 구체화:** “세 과목 중 어떤 개념을 공부하고 싶나요?”처럼 목표를 좁히는 질문을 한다. 구체화한 목표로 다시 확인할 수 있도록 기존 입력을 유지한다.
- **수정·재시도:** 범위 밖이나 불명확 결과를 받은 뒤 SCOPE-02처럼 지원 범위 안의 목표로 수정해 다시 제출한다. 수정한 목표를 서버에서 확인한 뒤 공부를 시작할 수 있어야 한다. 서버 연결 실패는 재시도할 수 있는 오류로 표시한다.

이 사례는 FE·BE 계약을 검토할 때 사용할 기대 결과다. 응답 코드와 요청 경로는 연동 방식이 확정되면 연결하고, 실행 결과는 이후 기록한다.
